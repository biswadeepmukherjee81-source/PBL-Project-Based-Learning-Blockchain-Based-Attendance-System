Why this project exists

A grading system is only as good as the record it keeps.

Attendance decides exam eligibility, yet the record of it usually lives in one spreadsheet, editable by one person, with no trace of what changed. This project treats that as a systems problem, not just a policy one.

The gap

Centralized records are easy to quietly edit

A conventional spreadsheet or database has no built-in audit trail. Faculty credentials can be shared or spoofed, proxy entries go unnoticed, and by the time discrepancies surface at semester-end, there's no reliable way to reconstruct what actually happened.

The prototype

Push attendance logic onto an immutable ledger

Every attendance transaction is written through smart-contract logic instead of a direct database write, so it leaves a timestamped, tamper-evident trail. Performance analytics — attendance percentage, exam eligibility — are then computed directly from that record.

Foundations

What blockchain actually contributes here

Four properties of a distributed ledger, and how each one maps onto an attendance problem specifically.

◆

Distributed ledger

Records are written chronologically across a shared ledger rather than a single editable table — there's no single point where history can be rewritten.

◇

Tamper resistance

Once an entry is committed, altering it leaves evidence of the change instead of silently overwriting the old value.

◈

Traceability

Every attendance transaction carries a verifiable history — who marked it, when, and against which student ID.

◉

Smart contracts

Recording and retrieval logic runs as predefined code, so the same rules apply to every entry with no manual discretion.

System architecture

Student → faculty → blockchain → analytics

The prototype follows one linear path from raw input to a performance figure a student can actually check.

01

Attendance input

Student details and session info are entered through the application interface.

02

Smart contract

The entry is processed according to predefined contract logic — not a raw database write.

03

Blockchain record

The transaction is committed to the ledger with a timestamp and hash.

04

Retrieve records

Full attendance history for a student can be queried back out on demand.

05

Analytics

Attendance percentage and eligibility are calculated straight from the retrieved record.

Where this connects to the console

The mid-term prototype establishes provider discovery and client-side state. The end-term release routes attendance submissions through an authenticated signer into the deployed contract.

1. Frontend collects the attendance payload
2. Signer requests an ECDSA signature via MetaMask
3. Contract executes markAttendance() on-chain
4. UI verifies via the AttendanceLogged event log
